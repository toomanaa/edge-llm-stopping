# Data

This folder has three datasets. All of them were built for this project.

## commands.jsonl

333 smart-home voice commands with the correct tool call for each one.
They cover lights (dim, on, off), thermostat, locks, blinds, media,
timers, and fans, across 6 rooms (plus the front door, back door, and
garage for the lock commands). Exactly 100 commands are "corrections",
like "turn off the lights... actually just dim them to 25%". For these,
the correct answer is the corrected command, not the first one spoken.
The commands were generated by a program, not scraped or taken from an
existing benchmark.

Each line looks like this:

    {"id": "cmd_0000", "utterance": "...", "ground_truth": "dim(bedroom, 25)", "family": "lights_dim", "has_correction": false}

## qa.jsonl (first QA set)

304 short factual questions (world capitals, basic science, history,
culture). Each question has a list of acceptable answers, so different
ways of writing the same answer (like aliases) still count as correct.
These were written by hand, not taken from a benchmark like TriviaQA or
NQ-open, so there are no licensing limits on sharing them.

This set was used for the first, preliminary QA experiment.

Each line looks like this:

    {"id": "qa_0000", "question": "What is the largest city in Japan?", "answers": ["tokyo"]}

## qa_v2.jsonl (larger QA set)

1,074 questions: 434 short factual questions and 640 "explain / why"
questions (like "what causes X" or "explain how X works"). We built this
set after finding that the first one had almost no hard stopping points,
because most answers were only one sentence. The explain / why questions
produce longer answers, which give many more real stopping decisions.

How answers are checked:

- Factual questions: the answer must match one of the accepted answers.
- Explain / why questions: the answer must contain all of the required
  concept keywords. Different forms of a word (like "align" and
  "alignment") count as a match.

This set is used for training and testing the probe and for all later
experiments.

Each line looks like this:

    [PASTE ONE REAL LINE FROM qa_v2.jsonl HERE]

## Regenerating

The QA v2 set was built by a short Python script with a fixed random
seed, so it can be rebuilt exactly. The script is in
`scripts/generators/`. The commands and first QA set were also built by
short scripts, and the `id` order is fixed by the seed.
